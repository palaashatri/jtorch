# ADR 0006: Declared scope for M4 (dense vision, 1D FFT, ONNX import foundations)

- Status: accepted
- Date: 2026-11-06

## Context

M0–M3 are complete for the automated reference scope (ADR 0005). M4 (DESIGN §34) delivers broad dense
operator compatibility and the Vision Inspector: indexing, scatter/gather, linalg, convolution, pooling,
normalization, FFT foundations, image transforms, ResNet/ViT breadth, ONNX/Safetensors adapters, attribution
gradients and the inspector app. This ADR records what this build actually implements and tests against
PyTorch 2.11.0 fixtures.

## Decision

M4 is complete for the automated reference scope as delimited below; manual screen-reader/GUI acceptance
remains human work. The repository reports exactly what is implemented and tested and records everything else
as `unsupported` in `compat/`.

Implemented and oracle-tested (PyTorch 2.11.0):

- 107 schema-declared public operators (`aten`) with CPU and meta kernels; 86 are declared `full-semantics`,
  16 `autograd`, 5 `forward` (generated by `tools/opgen` from `schema/ops`). The 21 non-promoted operators
  are: pooling/convolution/normalization (`conv2d`, `max_pool2d`, `avg_pool2d`, `adaptive_avg_pool2d`,
  `batch_norm`, `layer_norm`, `group_norm`), image/activation/loss restrictions (`constant_pad_nd`,
  `interpolate`, `gelu`, `embedding`, `cross_entropy`, `mse_loss`), composites (`linear`, `log_softmax`,
  `softmax`), `prod` (forward only) and `rand`/`randn`/`randint` (nondeterministic, no value parity).
- `complex64`/`complex128` dtypes (interleaved real/imag) with promotion `bool < int < float < complex`,
  complex `requiresGrad`, checkpoint codec support, and explicit rejection of complex in real-only kernels.
- 1D FFT foundations: `aten::fft_fft`, `aten::fft_ifft`, `aten::fft_rfft`, `aten::fft_irfft` with `n`
  padding/trimming, arbitrary `dim`, `backward`/`ortho`/`forward` norms, PyTorch permuted output strides,
  and reverse-mode adjoints via internal `fft_*_backward` helpers. 2D/nD FFT (`fft2`/`fftn` and shift
  variants) is not implemented.
- ONNX import foundations in `interop/jtorch-onnx` (opset 13–23, no third-party runtime deps, hand-written
  protobuf wire parser): `Identity`, `Add`, `Sub`, `Mul`, `Div`, `Neg`, `Abs`, `Exp`, `Log`, `Sigmoid`,
  `Relu`, `MatMul`, `Gemm`, `Softmax`, `Flatten`, `Transpose`, `Reshape`, `Concat`, `Squeeze`, `Unsqueeze`,
  `Gather`, `Conv`/`MaxPool`/`AveragePool` (NCHW 4-D, symmetric pads only), `Constant`, `BatchNormalization`
  (inference). Inference runs under `noGrad`; unsupported operators are reported before execution.
  ONNX export and external tensor data are not implemented.
- Remaining M4 scope from ADR 0005: grouped convolution, ceil-mode/adaptive pooling with divisor override,
  `interpolate` (nearest/bilinear), `gelu` (exact/tanh), `embedding` (padding/frequency/sparse rejection),
  batch/layer/group normalization, gather/index_select/slice/scatter, padding/flip, multi-head attention,
  transformer encoder layers, ResNet9/ViT fixture models (Safetensors), attribution saliency, and the
  `vision-inspector` demo (batch classification, saliency overlay, JSON/CSV export, corrupt-image isolation,
  and off-EDT `SwingWorker` decode/inference with 4096-side/16M-pixel decoded-size limits).

## Consequences

- README and `compat/` must not call the framework "PyTorch-class" or "drop-in".
- Each unsupported item has a clear failure mode rather than a silent fallback or dtype coercion.
- Advancing past M4 (M5 transforms, M6 search, M7 optimized CPU, M9+ accelerator/compiler work) requires
  the gates in DESIGN §34; 2D/nD FFT, ONNX export/external data, channels-last and higher-order autograd
  remain explicitly future work.
